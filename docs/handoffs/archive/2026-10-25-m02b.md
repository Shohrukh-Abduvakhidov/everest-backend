# M02B completion handoff

M02B implemented `POST /api/v1/auth/register` and `POST /api/v1/auth/login/password` without schema or dependency changes.

Registration validates allowed fields, normalizes E.164 input, validates names and passwords, hashes with salted asynchronous `scrypt`, and atomically creates the pending user, profile, unverified phone, password, student role, and audit event. Database uniqueness resolves concurrent phone registration to one success and one stable conflict.

Password login returns generic invalid credentials for unknown phones and wrong passwords, performs dummy-hash work for unknown phones, locks and rechecks the account, requires `active`, and atomically creates the shared session, updates `last_login_at`, and audits success. Access tokens remain only in the HttpOnly cookie.
